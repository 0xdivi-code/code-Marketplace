# Deploying Kiln

A single-process Node application: a Hono API, an embedded or external
PostgreSQL database, private file storage, and a static React build. One owner,
one server, no third-party services required beyond a payment gateway and an
email provider.

This document is written so the store can be run without editing code. Anything
that would normally need a deploy — payment credentials, licence terms, email
toggles, homepage sections, products, prices, coupons, bundles — is editable in
the admin console.

---

## 1. What you need

| Requirement | Notes |
| --- | --- |
| Node 20+ | Node 22 LTS is what this is tested on |
| A host with a persistent disk | Source archives and the database live on disk |
| A domain | HTTPS is mandatory for secure cookies |
| A reverse proxy | Caddy (simplest) or Nginx |
| A crypto gateway account | NOWPayments; any other provider can be added |
| An email provider | Resend, or an SMTP relay |

No build tooling is needed on the server if you build before uploading.

---

## 2. Environment variables

Copy `.env.example` to `.env` on the server and fill it in. The file is
gitignored; secrets must never be committed.

### Required in production

| Variable | What it does | How to set it |
| --- | --- | --- |
| `NODE_ENV` | Must be `production`. Turns on HSTS, frame protection and the production payment guards. | `production` |
| `PUBLIC_BASE_URL` | Absolute origin used in emails, sitemaps and payment callbacks. | `https://your-domain.com` |
| `APP_ORIGINS` | Comma-separated browser origins allowed to call the API with cookies. Anything not listed gets no CORS approval. | `https://your-domain.com` |
| `STORAGE_SECRET` | HMAC key signing download URLs. **The app refuses to boot in production without a real value.** | `openssl rand -hex 32` |
| `STORAGE_DIR` | Private archive root. Must be outside the web root. | `/var/lib/kiln/storage` |
| `OWNER_EMAIL` / `OWNER_PASSWORD` | The first owner account, created on seed. | your own |
| `NOWPAYMENTS_API_KEY` | Gateway key. Without it, checkout refuses paid carts. | from NOWPayments |
| `NOWPAYMENTS_IPN_SECRET` | Verifies payment webhooks. Without it, no webhook can settle an order. | from NOWPayments |
| `RESEND_API_KEY` | Delivers transactional email. | from Resend |

### Optional

| Variable | Default | Purpose |
| --- | --- | --- |
| `API_PORT` | `8787` | Listen port |
| `PGLITE_DIR` | `.data/pg` | Embedded database directory |
| `DATABASE_URL` | — | Use an external PostgreSQL instead of PGlite |
| `MAIL_FROM` | `Kiln <receipts@kiln.dev>` | Sender identity |
| `SMTP_URL` / `SMTP_TOKEN` | — | HTTP-to-SMTP bridge, alternative to Resend |
| `TRUST_PROXY` | `false` | Set `true` only behind a load balancer you control |
| `UPLOAD_MAX_ZIP_BYTES` | 209715200 | Largest accepted source archive |
| `ALLOW_SANDBOX_IN_PRODUCTION` | — | Leave unset. Exists only for sealed staging. |

**Never commit `.env`.** It is already in `.gitignore`; verify with
`git check-ignore -v .env`.

## 3. Build and run

```bash
git clone <repo> /srv/kiln && cd /srv/kiln
npm ci
npm run build              # emits dist/ and typechecks the server

export $(grep -v '^#' .env | xargs)
npx tsx server/scripts/migrate.ts   # create/upgrade the schema
npx tsx server/scripts/seed.ts      # first run only: catalogue + owner account
npx tsx server/index.ts             # or use the systemd unit below
```

`seed.ts` is safe to run repeatedly: it short-circuits when a catalogue exists.
`reseed.ts` is destructive and refuses to run with `NODE_ENV=production`.

### Health check

```bash
curl -fsS http://127.0.0.1:8787/api/health
# {"ok":true,"database":"reachable","version":"PostgreSQL …"}
```

Point your monitoring at this. It touches the database, so it catches a disk or
lock problem that a plain TCP check would miss.

## 4. Reverse proxy and HTTPS

The browser talks to one origin: the API serves `/api/*` and the static build is
served from `dist/`. Rewrite `/robots.txt` and `/sitemap.xml` to the API host, or
crawlers will fetch the SPA shell instead of the generated files.

### Caddy (automatic HTTPS)

```caddyfile
your-domain.com {
    encode zstd gzip

    # Search-engine files are generated by the app.
    rewrite /robots.txt  /api/robots.txt
    rewrite /sitemap.xml /api/sitemap.xml

    # Long-lived hashed assets.
    @assets path /assets/*
    header @assets Cache-Control "public, max-age=31536000, immutable"

    handle /api/* {
        reverse_proxy 127.0.0.1:8787
    }
    handle /robots.txt {
        reverse_proxy 127.0.0.1:8787
    }
    handle /sitemap.xml {
        reverse_proxy 127.0.0.1:8787
    }
    handle {
        root * /srv/kiln/dist
        try_files {path} /index.html
        file_server
    }
}
```

### Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    client_max_body_size 220m;   # source archives

    location = /robots.txt  { proxy_pass http://127.0.0.1:8787/api/robots.txt; }
    location = /sitemap.xml { proxy_pass http://127.0.0.1:8787/api/sitemap.xml; }

    location /api/ {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;   # large downloads
    }

    root /srv/kiln/dist;
    location / { try_files $path /index.html; }

    location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }
}
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

Set `TRUST_PROXY=true` when running behind either proxy so rate limiting keys on
the real client address.

## 5. systemd unit

```ini
[Unit]
Description=Kiln marketplace
After=network.target

[Service]
Type=simple
User=kiln
WorkingDirectory=/srv/kiln
EnvironmentFile=/srv/kiln/.env
ExecStart=/usr/bin/npx tsx server/index.ts
Restart=always
RestartSec=5

# Hardening: the app only needs its own directory and a writable storage root.
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/srv/kiln/.data /var/lib/kiln/storage

[Install]
WantedBy=multi-user.target
```

```
systemctl enable --now kiln
journalctl -u kiln -f
```

## 6. Backup and restore

Two things hold state and both must be backed up together: the database and the
private archives. A database row pointing at a missing archive is a broken
product.

```bash
# nightly, as the kiln user
npx tsx server/scripts/backup.ts /var/backups/kiln
```

`backup.ts` writes a timestamped directory containing a database dump, a tar of
the storage root, and a manifest with checksums. Copy it off the machine — a
backup on the same disk is not a backup.

Restore:

```bash
systemctl stop kiln
npx tsx server/scripts/restore.ts /var/backups/kiln/2026-11-05T02-00-00
systemctl start kiln
```

Verify a restore quarterly against a scratch host. An untested backup is a
guess.

**Retention:** keep 7 daily, 4 weekly, 12 monthly. The storage root grows with
every product version, so check free space before a deploy.

## 7. Logging and monitoring

The app logs one line per request and errors to stdout/stderr; systemd captures
both. Watch for:

| Signal | Meaning |
| --- | --- |
| `[api] Error: …` | An unhandled server error. The user saw a 500. |
| `webhook … signature rejected` | Someone is posting to `/api/webhooks`. Investigate. |
| `✉ … failed` | Email delivery failed. Visible in Admin → Notifications too. |
| `/api/health` non-200 | Database unreachable or locked. |

Admin → Webhooks shows every inbound payment callback with its signature
verdict. Admin → Notifications shows every outbound email and the active
transport. Both are the fastest way to answer "did the customer get it?".

Suggested alerts: health check failing twice in a row; failed webhooks above
zero; disk below 15% free.

## 8. Going live checklist

Run through this once, in order, on the real domain.

1. `NODE_ENV=production`, `PUBLIC_BASE_URL` and `APP_ORIGINS` set to the real
   origin — not localhost.
2. `STORAGE_SECRET` is 32 random bytes. The app will not start otherwise.
3. `STORAGE_DIR` is outside the web root and not world-readable:
   `chmod 700 /var/lib/kiln/storage`.
4. `NOWPAYMENTS_API_KEY` and `NOWPAYMENTS_IPN_SECRET` set; IPN URL in the
   NOWPayments dashboard points at
   `https://your-domain.com/api/webhooks/nowpayments`.
5. `RESEND_API_KEY` set. Admin → Notifications must **not** say "Development
   log".
6. Migrations applied; `seed.ts` run; owner password changed from the seed value
   and 2FA enabled at first admin login.
7. Buy one product end to end with real money, at the lowest price in the
   catalogue. Confirm: invoice, webhook verdict "signature valid", order paid,
   library access, download works, receipt email arrives.
8. Refund that test order; confirm licences revoke and the refund email arrives.
9. Visit `/robots.txt` and `/sitemap.xml` on the real domain; both must return
   the generated files, not the SPA shell.
10. Submit the sitemap in Google Search Console.
11. Nightly backup runs and a test restore succeeded.
12. `curl -I https://your-domain.com/api/catalog` shows
    `strict-transport-security`.
13. The sandbox gateway is gone: `POST /api/webhooks/sandbox/x/pay` returns 404.

## 9. Upgrading

```bash
git pull
npm ci
npm run build
systemctl restart kiln     # migrations run on boot
```

Migrations are idempotent and applied automatically at startup. Take a backup
first: a migration that adds a column is safe to re-run, a restore is not free.

---

## 10. Admin setup

1. Sign in at `/admin/login` with `OWNER_EMAIL` / `OWNER_PASSWORD`.
2. Change the password immediately, then enable two-factor.
3. **Store settings** — store name, support address, currency display.
4. **Licence terms** — seat counts and summaries for each tier. These appear on
   every product page and certificate; edit them here, not in code.
5. **Payments** — paste gateway keys if you prefer to keep them in the database
   rather than the environment. Environment values win when both are set.
6. **Notifications** — turn individual emails off, and confirm the transport is
   not "Development log".
7. **Products** — create, upload the source archive, set tiers, publish.
8. **Homepage & banners** — reorder, hide or rewrite the storefront sections.
9. **Coupons** and **Bundles** — run a promotion without a deploy.

Every admin action is written to the activity log with the actor, the action and
the affected record.
